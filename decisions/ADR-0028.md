# ADR-0028：协议信封 ↔ 落盘状态跨层绑定契约

- **ID**：ADR-0028
- **对应审计项**：#28（R3， harness-iteration-loop.md §10.2 台账）
- **状态**：ACCEPTED（契约已实现并通过自动验证；契约 1–4 的语义终审属人工确认点，见 §6）
- **决策日期**：2026-11-18
- **相关契约**：result_envelope v2.4 · 八阶段状态机 · `_state.json` schema

## 1. 背景（Context）

审计 #28 实锤（R7 Phase A）：协议层信封 `phase=EXECUTE`、`task_id` 与落盘状态完全不符时，
`protocol_check.py` 仍返回空失败列表（rc=0）——协议校验层与状态机层之间**没有绑定契约**。
信封语义正确 ≠ 信封与当前落盘任务对得上，这是两层各自校验都覆盖不到的盲区。

## 2. 问题（Problem）

补跨层断言的前提是先定义「哪个信封匹配哪个 `task_id`、`phase` 如何对齐、`turn` 是否必报」。
这属语义契约缺口（非纯代码 bug），台账 §10.2 #28 标「未闭环·设计缺口·登记备查」，需裁决。

## 3. 裁决（Decision）

采纳四条绑定契约（与上一轮报告草案一致），在 `protocol_check.py` 新增纯函数
`check_envelope_state_binding(env, state, phases) -> list[str]`（返回失败原因列表，空=通过）：

1. **绑定键**：信封 `task_id` 必须等于落盘 `task_id`（同一任务）。
2. **phase 对齐**：信封 `phase` ∈ {落盘当前 phase, 下一阶段}——允许在途信封（主理人已推进、
   落盘尚未更新），但不允许跳级或倒退。末阶段无后继时仅允许当前 phase。
3. **turn 在途**：若信封带 `turn`（且非 None），须 ∈ {落盘 turn, turn+1}；缺失不强制
   （向后兼容旧信封）。非整数 turn 判红。
4. **终态守卫**：落盘 `status ∈ {done, aborted}` 时，信封 `phase` 只能声明终态阶段
   `NEXT`——终态任务不得声称仍在执行中。

非 dict 信封 / 非 dict 落盘状态 / 空阶段序列 / phase 取值非法均判红（fail-closed）。

**挂载方式（零 CI 计数涟漪）**：跨层套件挂进现有 `protocol_check.py integration` suite
（语义契合：集成层本就校验信封↔状态），不新增 CI step、不改 GATES 计数、不动 §10.3.3 计数口径。
独立测试 `tests/test_cross_layer_binding.py` 覆盖正例 3 + 注入负例 5。

## 4. 实现（Implementation）

- `protocol_check.py`：
  - 新增常量 `TERMINAL_PHASE = "NEXT"`；
  - 新增纯函数 `check_envelope_state_binding`（复用 `load_state_phases`）；
  - 新增 `run_cross_layer_tests`（8 组用例：X1–X8）；
  - `main()` 的 `integration` 分支末尾追加跨层套件，失败计入 `failed`。
- `tests/test_cross_layer_binding.py`：`importlib` 按路径加载校验器（目录名含连字符），
  独立复现 X1–X8，不写仓库、不依赖本机私有环境。

## 5. 后果（Consequences）

- **正面**：堵住协议↔状态层的绑定盲区；在途信封仍放行（不破坏正常编排节奏）；
  零 CI 计数涟漪（不打乱 §10.3.3 / README / CONTRIBUTING 的三处一致）。
- **负面**：落盘状态未初始化（非 dict）时 `integration` 会新增失败项——这是期望的
  fail-closed 行为，调用方须先 `init`。
- **约束**：契约 2 的「下一阶段」依赖 `PHASES` 序列；未来调整阶段序列时，
  终态常量 `TERMINAL_PHASE` 须同步（X8 用例会捕获不同步）。

## 6. 状态说明（四态纪律）

- **自动验证通过**：独立测试 8/8 + `integration` 跨层套件 8/8 + `envelope` 回归 rc=0。
- **语义裁决（待人工确认）**：契约 1–4 的具体边界（尤其「在途信封允许下一阶段/turn+1」
  与「终态 phase=NEXT」）是人工语义终审点——本 ADR 记录 AI 依据审计草案与状态机语义的
  ACCEPTED 结论，**管家节点可推翻或调整**；改判后同步纯函数与 X1–X8 用例。
