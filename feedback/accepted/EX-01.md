# EX-01 · 发布介质自洽性的「硬证明」写法

**类型**：交付结果样例（工具与证据链）
**状态**：**AI 评估通过 / 待人工确认**（未经用户明确认可，不标人工确认通过）

## 1. 来源与证据（真实运行）

- v2.5.6 发布链：CI run `42823445006` = success（18 门禁 step + 6 平台 step），headSha `fcdf14b`。
- tag `v2.5.6` 对象 `061db48` 解引用到 `fcdf14b`；资产 `rot-v2.5.6.tar.gz` 14,752,316 B。
- 解包后 **63 个 tracked 文件逐文件 `git hash-object` 与 tag 的 blob hash 全等**；回下载 `cmp` 字节级一致；八处一致全等 `fcdf14b`；两处工作树 0 dirty。
- 台账：`docs/harness-iteration-loop.md` 变更记录末行；`CHANGELOG.md` [2.5.6]。

## 2. 为什么算好

- 没有用「已核对」「应该一致」这类口头结论，而是给出**可复跑的逐文件 hash 比对**：资产内容 == tag 内容是被证明的，不是被宣称的。
- 证据分层：CI 绿 → tag → archive → 解包核对 → release → 回下载 → 多源一致，每一环都有独立 rc 或 hash，缺一环不会伪装成整体通过。
- 发现异常时按退出码分层纪律先查命令本身（`gh api` 误传 `-R`、解包断言范围过宽），没有把工具问题误报成内容缺陷。
- **边界诚实**：明确写出该样例证明的是「包自洽」，不是「任务产出质量好」。

## 3. 可复跑命令

```bash
git ls-tree -r v2.5.6                      # tag 侧 blob hash 清单
git hash-object <解包后的每个文件>          # 资产侧，逐文件比对
gh release download v2.5.6 --pattern 'rot-v2.5.6.tar.gz' --dir /tmp && cmp <本地> <回下载>
python3 scripts/rot.py check               # 本轮新增：一条命令复跑全部门禁并落盘证据
```

## 4. 仍需人工判断的部分

「这个交付是否解决了用户真正的问题」不在本样例的证明范围内，属于语义与价值判断（workmap A10/A11），须由用户确认。
