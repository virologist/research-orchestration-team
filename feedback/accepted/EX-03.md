# EX-03 · 一条负例只承载一个失败维度

**类型**：检查设计样例（好检查长什么样）
**状态**：**自动验证通过**（脚本实跑可复现）+ **AI 评估通过 / 待人工确认**（作为「好样例」的判断）

## 1. 来源与证据（真实运行）

- `scripts/workmap_check.py --self-test` 实跑 7 组注入破坏，每组**只命中预期的一个检查项**：
  `W3 依赖环 → ['W3']`、`W4 工具缺失 → ['W4']`、`W6 规则缺检查 → ['W6']`、`W7 引用不存在阶段 → ['W7']`、
  `W10 人读视图缺 ID → ['W10']`、`W11 转化优先级被改 → ['W11']`、`W12 样例断言漂移 → ['W12']`。
- `scripts/sample_check.py --self-test` 实跑 9 条断言正例 PASS / 反例 FAIL，全部 `ALL GREEN`。
- 历史依据：`README.md`「负例设计的两条硬纪律」；`docs/REDTEAM-REPORT.md` C1（负向用例 expected 不参与断言导致假绿）。

## 2. 为什么算好

- 每条负例只破坏**一个**维度，失败项列表里没有无关检查项 → 证明「是这条规则在拦」，而不是「随便哪里报错都算检出」。
- 断言同时校验退出码翻转**和**失败原因归属；只断言 rc 会让检查项本身失效也被误判通过。
- 注入前锚点唯一命中、注入后断言落盘（旧串消失、新串出现），避免静默空转的假绿。
- 自测自带，不依赖人工记忆去「记得验证校验器」。

## 3. 可复跑命令

```bash
python3 scripts/workmap_check.py --self-test   # 7 组注入破坏
python3 scripts/sample_check.py --self-test    # 9 条断言正/反例
python3 scripts/workmap_check.py -v            # W1–W12 正向校验
```

## 4. 仍需人工判断的部分

「这些检查项是否覆盖了真正重要的风险」属设计判断，脚本只能证明检查**有效**，不能证明检查**完备**；完备性由 `workmap_check.py W12` 与 `rot.py verify` 的差集核对部分承接，仍建议人工复核一次。
